# CLAUDE.md

## Overview

Personal solutions to [exercism.org](https://exercism.org) exercises, currently covering the Gleam track only. There is no shared library and no application here - every exercise is a standalone, self-contained Gleam project under `gleam/`.

`AGENTS.md` at the repo root is a symlink to this file; edit `CLAUDE.md` and both stay in sync.

## Commands

`just --list` for the full set, `CONTRIBUTING.md` for the table. What neither says:

- `just check` (lint then test) is the only gate - there are no GitHub Actions workflows
- `just test` compiles and runs every project and is slow; iterate with `just test-exercise <dir>`
- `EXERCISE` is the kebab-case directory name, not the snake_case package name

## Structure

Each `gleam/<exercise-name>/` is one Gleam project: kebab-case directory, snake_case package name in `gleam.toml`, solution in `src/<package_name>.gleam`, tests in `test/<package_name>_test.gleam`.

The directory/package naming split is load-bearing: directory `high-school-sweetheart` -> package, module, and file `high_school_sweetheart`. A Gleam module's name is its path under `src/` or `test/`, and `gleam test` runs the `<package_name>_test` module - so the test file name must match `gleam.toml`'s `name`.

Exercise directories are downloaded with the `exercism` CLI, not hand-created, and are submitted back with `exercism submit src/<package_name>.gleam`. `README.md`, `HELP.md`, and `HINTS.md` come with them, generated by the platform: they state the problem, they are not this repo's documentation, and they are not yours to edit. Only `src/` is.

## Test conventions

Tests use `exercism_test_runner`, not `gleeunit`. The shape is fixed by the runner:

- `pub fn main() { test_runner.main() }` is the entry point
- every test is a zero-argument `pub fn <name>_test()`; the `_test` suffix is how the runner discovers it
- most assertions come from `exercism/should`, which exports exactly one function, `equal`, piped into: `subject |> should.equal(expected)`
- a few older suites never import `exercism/should` and assert with bare `let assert True = ...` instead

Test files ship with the exercise and encode the exercise's canonical data. Treat them as the specification: solve `src/` against the given tests rather than editing them. `gleam test` runs a whole project's suite - there is no per-test filter, so narrowing means picking the exercise directory.

## Dependencies

Every exercise pins `gleam_stdlib` below `0.60.0`. This is deliberate: `exercism_test_runner` breaks against stdlib 0.60+, so `just update` must not be allowed to lift that ceiling. Two generations of projects coexist - older ones on `exercism_test_runner ~> 1.4` / `gleam_stdlib >= 0.32.0`, newer ones on `~> 1.9` / `>= 0.54.0`. Both are fine; match whatever a given exercise already has rather than normalizing across the tree.

## Style

`gleam format` is authoritative for `.gleam` files; `.editorconfig` covers the rest. `CONTRIBUTING.md` carries the commit and branch conventions.
