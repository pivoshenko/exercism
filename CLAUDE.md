# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Personal solutions to [exercism.org](https://exercism.org) exercises. Only the **Gleam** track is present today: `gleam/<exercise-slug>/` holds 39 independent, self-contained Gleam projects. There is no root-level Gleam project, no shared library, and no CI — the `justfile` is the only orchestration layer, and it works by iterating `gleam/*/` and shelling into each one.

## Commands

All recipes run from the repo root (`just` with no args lists them):

```sh
just install   # only prints `gleam --version` — installs nothing
just format    # gleam format across every exercise
just lint      # gleam format --check across every exercise
just test      # gleam test across every exercise
just check     # lint + test
just update    # gleam deps update across every exercise
```

Work on a single exercise (the normal loop — `just test` compiles all 39 projects and is slow):

```sh
just solve two-fer                    # cd gleam/two-fer && gleam test
cd gleam/two-fer && gleam test        # equivalent
cd gleam/two-fer && gleam format      # format just this one
```

There is no way to run a single test function — `exercism_test_runner` discovers and runs every `*_test` function in the exercise's test module.

Toolchain in use: gleam 1.18.1, just 1.58.0.

## Exercise anatomy

Each `gleam/<slug>/` directory is a full Gleam project generated by the `exercism` CLI:

- `src/<module>.gleam` — **the only file you write**. `HELP.md` confirms the submission is `exercism submit src/<module>.gleam`.
- `test/<module>_test.gleam` — supplied by Exercism. It defines `pub fn main() { test_runner.main() }` plus one `pub fn <case>_test()` per case, using `exercism/should` (not `gleeunit`). Treat as read-only; changing it invalidates the exercise.
- `README.md`, `HELP.md`, `HINTS.md` — generated exercise text, not hand-written docs. Don't edit.
- `gleam.toml` / `manifest.toml` — per-exercise; `manifest.toml` is checked in and regenerated by `just update`.
- `build/` and `.exercism/` are gitignored (per-exercise `.gitignore` and the root one respectively).

### Naming

The directory is the kebab-case Exercism slug; the Gleam package `name`, the module file, and the test module are all snake_case derived from it — `gleam/high-school-sweetheart/` → `name = "high_school_sweetheart"`, `src/high_school_sweetheart.gleam`, `test/high_school_sweetheart_test.gleam`. Keep all four in sync when adding an exercise.

### Two dependency baselines

Exercises were fetched at different times, so `gleam.toml` comes in two shapes and they are not unified:

- older (10 exercises, e.g. `two-fer`): `exercism_test_runner ~> 1.4`, includes `gleam_bitwise`, `gleam_stdlib ~> 0.32 or ~> 1.0`
- newer (29 exercises, e.g. `accumulate`): `exercism_test_runner ~> 1.9`, adds `gleam_yielder`/`gleam_regexp`/`gleam_deque`, `gleam_stdlib >= 0.54.0 or ~> 1.0`

Leave a fetched exercise's `gleam.toml` as-is; don't "align" it with its neighbours.

## Conventions

- `gleam format` is the sole formatter and `just lint` is `gleam format --check` — run it before finishing. `.editorconfig` (LF, 2-space, 120 cols, final newline) covers the non-Gleam files.
- Existing solutions lean on the pipe operator and `case` expressions over nested calls; match that style.
- Commits follow Angular conventional commits (`feat:`, `docs:`, `style:`, `chore:`, `build:`), scoped to one concern.
