# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Personal solutions to [exercism.org](https://exercism.org) exercises. Only the **Gleam** track exists: `gleam/<exercise-slug>/` holds 39 independent, self-contained Gleam projects. There is no root-level Gleam project, no shared code between exercises, and no CI — the root `justfile` is the only orchestration layer, and it works by looping over `gleam/*/` and shelling into each directory.

## Commands

All recipes run from the repo root (`just` with no args lists them):

```sh
just install   # only prints `gleam --version` — installs nothing
just format    # gleam format in every exercise
just lint      # gleam format --check in every exercise
just test      # gleam test in every exercise
just check     # lint + test
just update    # gleam deps update in every exercise
```

Work on a single exercise (the normal loop — `just test` compiles all 39 projects and is slow):

```sh
just test-exercise two-fer                    # cd gleam/two-fer && gleam test
cd gleam/two-fer && gleam test        # equivalent
cd gleam/two-fer && gleam format      # format just this one
```

There is no finer test granularity: `exercism_test_runner` discovers and runs every `pub fn *_test()` in the exercise's test module.

Toolchain in use: gleam 1.18.1, just 1.58.0.

## Exercise anatomy

Each `gleam/<slug>/` is a full Gleam project as fetched by the `exercism` CLI:

- `src/<module>.gleam` — **the only file you write**. Submission is `exercism submit src/<module>.gleam` (see any exercise's `HELP.md`).
- `test/<module>_test.gleam` — supplied by Exercism: `pub fn main() { test_runner.main() }` plus one `pub fn <case>_test()` per case, asserting via `exercism/should` (not gleeunit). Treat as read-only; editing it invalidates the exercise.
- `README.md`, `HELP.md`, and (in 19 exercises) `HINTS.md` — generated exercise text, not hand-written docs. Don't edit.
- `gleam.toml` / `manifest.toml` — per-exercise; `manifest.toml` is checked in and regenerated by `just update`.
- `build/` is ignored by each exercise's own `.gitignore`; `.exercism/` metadata by the root one.

### Naming

The directory is the kebab-case Exercism slug; the package `name` in `gleam.toml`, the source module, and the test module are all snake_case derived from it — `gleam/high-school-sweetheart/` → `name = "high_school_sweetheart"`, `src/high_school_sweetheart.gleam`, `test/high_school_sweetheart_test.gleam`. Keep all four in sync when adding an exercise.

### Two dependency baselines

Exercises were fetched at different times, so `gleam.toml` comes in two shapes that are deliberately not unified:

- 29 exercises (e.g. `bob`, `two-fer`): `exercism_test_runner ~> 1.4`, include `gleam_bitwise`, `gleam_stdlib ~> 0.32 or ~> 1.0`
- 10 exercises (e.g. `accumulate`): `exercism_test_runner ~> 1.9`, add `gleam_yielder`/`gleam_regexp`/`gleam_deque`, `gleam_stdlib >= 0.54.0 or ~> 1.0`

Leave a fetched exercise's `gleam.toml` as-is; don't "align" it with its neighbours.

## Conventions

- `gleam format` is the sole formatter and `just lint` is `gleam format --check` — run it before finishing. `.editorconfig` (LF, 2-space indent, 120 cols, final newline) covers non-Gleam files.
- Existing solutions favour the pipe operator and `case` expressions over nested calls; match that style.
- Commits follow Angular conventional commits (`feat:`, `docs:`, `style:`, `chore:`, `build:`), one concern per commit.
- PRs use `.github/PULL_REQUEST_TEMPLATE.md`.
